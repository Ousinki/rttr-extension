# RTTR 音标系统架构文档

## 当前实现方案 (v0.2 — 已落地)

### 架构：Free Dictionary API + 严式→宽式 KK 符号清洗

采用 **"AI 只负责翻译 + 音标由独立引擎查询"** 的关注点分离架构。

#### 数据流
```
用户划词 → Compromise.js 分词 → AI 翻译(仅语义) ──┐
                                                     ├→ 合并结果 → 渲染到页面
                     Free Dictionary API(音标) ──────┘
```

#### 核心模块：`utils/phonetics.ts`
- **数据源**：`https://api.dictionaryapi.dev/api/v2/entries/en/{word}` (基于 Wiktionary，完全免费，无需 API Key)
- **符号清洗**：Wiktionary 返回的是严式 IPA，通过 `narrowToKK()` 函数转换为中国大陆通用的宽式美式音标 (KK)
  - `ɹ` → `r` (齿龈近音 → 普通 r)
  - `ɫ` → `l` (dark L → 普通 l)
  - `ɾ` → `t` (闪音 → t)
  - `ɚ` → `ər` (R 色彩化央元音)
  - `ɝ` → `ɜːr` (R 色彩化半开央元音)
  - 去除音节分隔点 `.` 和塞擦音连字符 `t͡ʃ` → `tʃ`
- **优先级**：优先选取带有美式发音音频 (`-us.mp3`) 的条目
- **并发控制**：最大并发 5 个请求，3 秒超时，防止被限流
- **内存缓存**：同一会话内相同单词不重复请求
- **容错**：音标查询失败不影响翻译结果返回

#### AI 提示词优化
- 从原来的 4 列输出 (`原文|翻译|解释|音标`) 精简为 3 列 (`原文|翻译|解释`)
- 明确禁止 AI 输出音标，节省 Token 和生成时间

## 未来升级方案 (备选)

### 方案 A：ECDICT 离线库提取
- **来源**：`skywind3000/ECDICT` (GitHub, 7.7k stars, MIT License)
- **优势**：340 万词条，包含符合国内习惯的音标
- **劣势**：原库上百 MB，需要构建期脚本提取纯音标 JSON
- **适用场景**：需要离线使用、追求极致零延迟

### 方案 B：CMU Pronouncing Dictionary + ARPAbet→IPA 转换
- **来源**：卡内基梅隆大学官方发音词典
- **优势**：13.4 万词，学术黄金标准
- **劣势**：需要手写映射算法（AH0→ə, AH1→ʌ 等）
- **适用场景**：需要极高学术准确性

### 方案 C：混合策略 (终极方案)
1. **第一层**：本地 JSON 离线词典 (ECDICT 提取) — O(1) 瞬间命中
2. **第二层**：Free Dictionary API — 离线库未命中时的在线回退
3. **第三层**：静默跳过 — 两者都查不到时不显示音标
